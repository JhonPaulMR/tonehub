      📌 Informações Gerais

      Bem-vindos! 

      Esta disciplina será ministrada na modalidade EAD, ou seja, aulas realizadas de forma assíncrona, com materiais, videoaulas e atividades concentradas aqui no Moodle institucional. Nosso meio de comunicação oficial será o Discord oficial do curso, no canal da disciplina. O desenvolvimento de aplicações web norteado por frameworks é uma prática consolidada, neste contexto, o uso de frameworks Backend consiste da geração de conteúdo e renderização de páginas no lado servidor, entregando ao cliente somente os recursos já processados, promovendo maior segurança e controle das operações. Para entender a disciplina de Desenvolvimento de Aplicações Backend com Framework é necessário ter cursado com sucesso a disciplina de Desenvolvimento de Aplicações Backend visto que os conceitos dessa disciplina são fundamentos para o uso de frameworks Backend.

       

      📖 AULAS

      São 15 módulos contemplando 5 temas de estudo, liberados semanalmente. A carga horária de cada módulo abrange atividades específicas a serem desenvolvidas, além de prever tempo para dedicação à prática de implementação, atividade a ser enviada até o final do curso.

      📖 04 | Roteamento e Ciclo de Vida de uma Request | 4h

      Tema de Estudo: Ciclo de vida da aplicação web com renderização no lado servidor
      Carga Horária: 4h
       

      Este módulo explora de modo prático o caminho percorrido pelos dados dentro do framework desde o início da requisição no Router até o retorno da Resposta. Neste caminho, são abordadas opções para organização do código, escrita de controllers e views.

      Nesta aula:

      1. Roteamento no Laravel

      2. Separação de responsabilidades: padrão MVC

      3. Rotas GET e POST

      4. Rotas nomeadas

      5. Conceito de Actions e Services

      Videoaula:

      • https://youtu.be/sMNU0sqn49k

       

      Exercício de fixação:

      • Dado o exemplo do vídeo (clone o repositório), crie uma página que contenha um formulário login de usuários;

      • Crie uma rota GET para desenhar esse formulário;

      • Crie uma rota POST para receber os dados do novo usuário e redirecione-o para a página de listagem de sujeitos em caso de sucesso;

      • Nesta mesma rota, crie um "redirect back" com uma mensagem de erro para estes casos: (1) o nome de usuário é vazio, (2) a senha possui menos de 6 caracteres.

      📖 05 | Views com Blade | 4h

      Tema de Estudo: Validação e persistência de dados
      Carga Horária: 4h
       

      Este módulo aborda a construção de páginas usando Blade, a template engine do Laravel. O Blade permite a mixagem de códigos PHP na construção de views HTML, incluindo recursos como a interpolação de valores, uso de condicionais, loops, componentes personalizados, entre outros.

      Nesta aula:

      1. Introdução ao Blade

      2. Server Side Rendering

      3. Inclusão de subviews

      4. Uso de condicionais

      5. Uso de loops

      6. Uso de Componentes

      7. Componentes com parâmetros

      Videoaula:

      • https://youtu.be/UoPNXXJwZGY

      Exercício de fixação:

      • Dado o código desta aula, disponível no branch "ead-modulo-05" do repopositório da aula, realize as seguintes alterações focando no aprendizado de Views Blade:

      • Crie a rota de listagem de atendimentos, você pode usar um modelo de dados minimalista (e usando dados fake, tal como na listagem de sujeitos), considere que o atendimento possui apenas uma "data" e uma "descrição", um exemplo de atendimento pode ser: "25/04/2025" - "O sujeito foi atendido pela assistente social Júlia, onde retratou os eventos ocorridos na semana. Foram dados os encaminhamentos necessários"; 

      • Implemente também uma rota para a criação de um novo atendimento, essa rota deve conter o formulário de registro de atendimentos. Use os mesmos atributos listados anteriormente: "data" e "descrição".

      • Faça com que essas novas rotas renderizem Views Blade no mesmo padrão adotado no resto da aplicação, use o layout admin e forneça títulos para as páginas.

      Atividades:

      📖 07 | Forms e Validação de Requisições | 4h

      Tema de Estudo: Validação e persistência de dados
      Carga Horária: 4h

      Este módulo aborda estratégias para a validação de dados no Laravel. O tratamento de dados em requisições é fundamental para garantir a segurança da aplicação e também uma boa usabilidade visto que o usuário pode ser norteado por boas mensagens de erro quando estes ocorrem. O conteúdo é tratado de forma prática, com exemplos tanto em rotas Web quanto em rotas de API.

      Nesta aula:

      1. Criando regras de validação

      2. Acessando os os erros de validação

      3. Tratando erro campo a campo

      4. Acessando a "old" request                         

      5. Criando uma classe específica para a Request

      6. Escrevendo as regras de validação na classe da Request

      7. Instalando a tradução das mensagens 

      Videoaula:

      • https://youtu.be/lVGBQNq3ggk

      Exercício de fixação:

      • Clone o projeto do vídeo;

      • Crie uma nova página que contenha um formulário para registro de atendimentos;

      • Neste formulário, crie 3 campos: data, descrição e encaminhamentos;

      • Crie uma classe específica para a request deste form, nela aplique as regras de validação que julgar necessárias;

      • Crie uma validação composta por 3 regras ao mesmo tempo;

      • Desafio: existem regras bem específicas que permitem criar comportamentos únicos em cada validação, como por exemplo “missing_if”. Investigue essa regra e tente aplicá-la em um dos campos no seu formulário;

      • Desafio sênior: O que acontece quando a sua regra de validação é tão específica que nenhuma regra se enquadra? É possível criar validações por Closure! Neste tipo de validação, você define uma função em PHP responsável por tratar os dados. Investigue este método e tente implementar um exemplo no seu formulário.

      Atividades:

      • Resolva o exercício de fixação, em seguida responda o questionário disponível neste módulo.

      Tema de Estudo: Ciclo de vida da aplicação web com renderização no lado servidor
      Carga Horária: 4h
       

      Este módulo explora alguns dos recursos para autenticação de usuários no Laravel. Existem diferentes estratégias que podem ser empregadas, desde o modelo com o middleware "auth" abordado nesta aula até mesmo Starter Kits que possuem toda a lógica já implementada.

      Nesta aula:

      1. Autenticação nos Starter Kits

      2. Pacotes Sanctum e Passport

      3. Como é feito o processo de Login?

      4. Protegendo rotas privadas com middleware

      Videoaula:

      • https://youtu.be/e075iZW1m-4

      Exercício de fixação:

      • Dado o código do módulo anterior (branch "ead-modulo-07" do repositório do vídeo), replique o exemplo da videoaula;

      • Na tela inicial (welcome) crie um link para a tela de registro de usuários;

      • Desafio: crie uma tela para troca de senhas, onde o usuário deve digitar: o email, a senha anterior, e duas vezes a senha nova (password e password_confirmation);

      • Aplique o middleware de autenticação em todas as rotas que devem ser privadas.

      💻 | Prática de Implementação

      Descrição da atividade:

      Chegou a hora de aplicar seus conhecimentos de maneira prática! Os módulos da disciplina visam fornecer o embasamento necessário para a construção de aplicações com o framework Laravel. Nesta atividade você terá a oportunidade de selecionar os tópicos que achou mais interessantes na disciplina e empregá-los construindo uma aplicação web.

      Não existe um tema pré-definido, você é livre para implementar qualquer ideia. Pode ser algo relacionado ao seu TCC, pode ser uma API, um site pessoal, pode ser um MVP de algum produto, enfim, aproveite a oportunidade para consolidar os conceitos vistos na disciplina e criar algo novo, dê preferência a ideias simples, que caibam no escopo e no tempo dedicado a esta disciplina.

      Critérios de avaliação:

      [1.5 ponto] Repositório no github com Readme:

      • O seu projeto deve estar hospedado publicamente no github, o link para acesso ao código-fonte não deve exigir login nem a adição do professor como colaborador no repositório.
      • Você deve criar um arquivo Readme.md na raiz do projeto, nele faça uma descrição da sua aplicação (o que ela faz, para que serve, quem é o público-alvo, etc), inclua um print da tela mais legal que você fez (dispensável caso a sua aplicação seja uma API). 
      • No arquivo Readme.md, inclua as instruções para configuração e execução da aplicação (quais comandos o professor deve executar para testar a sua aplicação localmente?). Não esqueça de deixar um arquivo .env.example caso seu projeto exija a configuração de variáveis de ambiente.
      • Cite (como uma lista) no Readme os 5 módulos da disciplina que você usou na implementação (veja mais detalhes no item seguinte).

      [6 pontos] Aplicação dos conceitos de (pelo menos) 5 módulos:

      • Selecione pelo menos 5 módulos da disciplina, podem ser os que você mais gostou ou ainda aqueles que melhor se encaixam na proposta da sua aplicação. Aplique esses módulos de maneira prática, implementando em código os conceitos abordados, construa funcionalidades usando o que foi mostrado na aula, organize o código, crie telas, formulários, validações, etc. Os módulos teóricos (como por exemplo 1, 2 e o 3) não serão considerados, só vale aquilo que você realmente aplicar na prática.
      • Este critério será avaliado da seguinte forma: 0,4 ponto para cada módulo aplicado de maneira coerente no projeto. Serão desconsiderados módulos onde não seja possível observar esforço notável do aluno, ex: "falar que aplicou o recurso X, mas na verdade o aluno não fez nada, o recurso sempre esteve lá desde a criação do projeto vazio do laravel".

      [2.5 pontos] Defesa do código em vídeo:

      • Gravar um vídeo apresentando o os pontos principais do código-fonte juntamente com a demonstração da aplicação desenvolvida;
        • Certifique-se de mostrar onde você aplicou pelo menos 5 módulos da disciplina no vídeo! Ao apresentar os módulos, siga a mesma ordem da lista de que você escreveu no Readme.
      • O vídeo deve ter no máximo 10 minutos;
      • Hospede o vídeo em serviços como o Youtube, Google Drive, Vimeo, etc;
        • O vídeo pode ser configurado como “Não listado”, mas o acesso pelo professor deve ser público (sem exigir login);
      • Roteiro para o vídeo:
        • Navegue por todas as telas demonstrando as funcionalidades, ou demonstre requisições nas rotas caso seja uma API;
        • Apresente brevemente como você aplicou os módulos da disciplina no projeto;
        • Comente sobre as principais dificuldades enfrentadas e perspectivas futuras para a aplicação.
      • Se possível, adicione a visão da Webcam no canto da tela, assim você aparece no vídeo também.
      • Dicas:
        • Você pode usar alguma ferramenta pronta, como o https://www.loom.com/ ou ainda gravar o vídeo usando o OBS Studio;
        • Para editar o vídeo, no Linux, uma ferramenta bacana é o kdenlive;
        • Treine antes de fazer a gravação;
        • Caso sinta necessidade, realize cortes com pequenos trechos, depois junte tudo na edição.
